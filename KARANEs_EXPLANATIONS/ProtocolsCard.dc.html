Protocols

契約書 / conform · SwiftUIの土台
からね プロトコル＝「このメソッド・プロパティは絶対持ってね」という契約書。中身は書かない、条件だけ決める。Dartの abstract class / implements と同じよ。
🍩 たとえ話でいくよ（友達との集合）
  • protocol = サイン入り契約書📜。「10時に東京駅集合」みたいな守るべき条件。
  • : Protocol = 契約にサイン（conform）✍️。守る側の型が名乗る。
  • 中身は自由 = 遅れて来てもOK（来方は各自）。でも来ないやつ＝そもそも存在できない（ビルドエラー）。

キーポイント

  • protocol は「何を持つべきか」だけ。実装は書かない。
  • struct X: Greetable で採用（conform）＝契約にサイン。
  • サインしたら必須メンバーを必ず書く。無いとビルドエラー。
  • 違う型でも [Greetable] でまとめて扱える（全員契約を守ってる保証）。

Dart / Java → Swift

元Swift
abstract class / interface→protocol
implements→:（コロンで採用）
契約を守る＝実装→conform（同じ）

コード例

protocol Greetable { var name: String { get } func greet() // 条件だけ。中身なし } struct Japanese: Greetable { // 契約にサイン var name: String func greet() { print("\(name)です") } // 中身は自由 } let people: [Greetable] = [Japanese(name: "はやと")] for p in people { p.greet() } // 全員greet()持ってる保証
⚠ 罠  conform したのに必須メンバーを書かないと does not conform to protocol でビルドが止まる。これが「寝坊した友達は存在できない」の正体。SwiftUIの struct ContentView: View の View もプロトコルよ。
