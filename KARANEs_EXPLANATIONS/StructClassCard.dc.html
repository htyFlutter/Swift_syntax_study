Structures & Classes

struct(コピー) vs class(共有)
からね Swift最大の山。struct と class、見た目そっくりだけど「コピーされる」か「共有される」かが真逆。ここだけはガチで別世界よ。
🍩 たとえ話でいくよ（超大事）
  • struct = 書類のコピー📄。b = a した瞬間コピーが刷られて別物。b に落書きしても a は無傷。
  • class = 1枚の書類にみんなで矢印🔗。b = a は矢印のコピー。b いじると a も変わる（Flutterのアレ）。

キーポイント

  • struct = 値型（コピーされる）← Swiftの主役。
  • class = 参照型（共有される）← Dartと同じ。
  • struct は init 自動、class は自分で書く。
  • 迷ったら struct。どうしても共有したい時だけ class。

Dart → Swift

DartSwift
全部 class（参照型）→struct が基本（値型）
b = a は共有→b = a はコピー（独立）
init は手書き→struct は自動生成

コード例

struct User { var name: String } var a = User(name: "はやと") var b = a // ★ここでコピーされる b.name = "太郎" print(a.name) // はやと ← 無傷！ // (class なら a も "太郎" に変わる)
⚠ 罠  「別の変数に入れたら元のデータも勝手に変わってた」ってFlutterのバグ、あれ参照型のせい。struct はコピーされるから、その事故が構造的に起きないの。
からね: struct で a が無傷だった時の "Whaaat!?"、忘れんな。教科書10回読むより、あの1回の驚きが一番効くのよ。
